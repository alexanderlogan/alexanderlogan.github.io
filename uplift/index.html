How it works

Six stages, one approval gate

Each stage is a plain-markdown skill or subagent in the project's .claude folder. The /run-pipeline command chains them and stops for a human decision before anything becomes work for engineering.

The product under discovery

Uplift: AI adoption analytics for knowledge workers

A fictional product chosen because it is the problem every organization rolling out AI tools faces now: leaders need proof of value, employees need trust. Four invented customer interviews pull in different directions.

The system

The team's playbook, written as skills

These are the actual files the agent runs. Because they are plain markdown, the method is portable across models and platforms, and a team can review and improve them like any other shared asset.

Principles

What this demonstrates for product teams

Humans decide, agents draft and challenge

The approval gate is built into the command, not left to discipline. Agents accelerate the work; accountability stays with the PM.

Evidence over assertion

Uncited research claims are not allowed. Requirements trace to themes; priorities show their arithmetic. Hallucinated insight has nowhere to hide.

Standards become shared assets

A team's best practice lives in skills anyone can run, review and improve, instead of in one power user's head.

Measure the cycle, not the logins

Adoption is proven by time from research to approved spec and by story rework rate, not by how often people open a tool.

Run it yourself

Three steps

  1. Copy the uplift folder to your machine.
  2. Open it in Claude Code: run claude in a terminal, or use the Code tab in the Claude desktop app.
  3. Clear the output folder and type /run-pipeline. Approve the PRD when asked.
